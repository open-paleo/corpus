# Conversion notes: marker, vision, translation, text repair

Gotchas in converting PDFs to markdown. Read alongside the "Conversion failure modes" table in the repo `CLAUDE.md`, which this file does not repeat.

## Before converting: probe the PDF

### Classify a PDF by its pages, not its filename
A file named like a supplement (Elsevier's `mmc2.pdf`) can hold the whole paper: a cover with graphical abstract, the article, then the supplement. The first few hundred characters of a few pages are not enough to tell. Before calling a file a supplement, a cover or a wrong paper, find where each part starts (`Introduction`, `Supplemental`, `References`) on every page.

### Probe the text layer before running marker on any scan
Marker with `--disable_ocr` passes through whatever embedded OCR the PDF has, and substitution garbage ("lhe lin;[ aJeguately known", "L'niver~ity", "Trrassic") evades `intake_qc.py` (high B/page), `qc_scan.py` (ASCII, not PUA) and the language audit (still English-ish). A file can pass at over 5,000 B/page fully garbled, and a clean title line does not mean a clean body.
Year is not a reliable guide: post-1900 letterpress scans (a 1940s USGS paper reading `CHARLES W. GILMOEE`, `SHOETEE CONTEIBUTIONS`) are as bad as older ones. For any scanned reprint, pre-2000 paper, or "Reproduced by ... Gateway" watermark, run the text-layer probe from CLAUDE.md first; if garbled, `scripts/intake_acquire.py KEY --vision-ocr "<reason>"` directly. After marker, read a real prose paragraph (`sed -n '5,15p'`) before declaring the file ok.

### Front-loaded text layer: probe a middle page, and read the tail on a stub flag
A non-zero text layer does not mean marker will work. A download cover can supply all of a PDF's text while the body is image-only (marker output under 100 B/page), or only page 1 can have a text layer, so marker stops mid-sentence and loses later tables.
Print a per-page character count (pypdfium2 loop over `get_text_bounded()`) rather than a total. When `intake_qc.py` flags `likely_stub`, run `tail -c 300 markdown/KEY.md`: the head is the part with a text layer, so it always looks fine; truncation shows at the tail (a sentence ending in a colon).

### 1900-1919 papers: decide by text-layer quality, not year
BAMNH, RSC Transactions, Comptes Rendus and JSTOR-scanned plate-heavy monographs of this era usually need vision: small-caps misreads (`BarRnuM Brown`, `Pirate XLII` for Plate XLII, `Wdmonton`, `LawrencE`), rotated plate captions extracted as CID garbage, and plate-diluted B/page that trips `likely_stub`. Pre-flag them with `intake_acquire.py --vision-ocr`.
US Government Printing Office products of the same era (USGS, Smithsonian) often have clean text layers, and marker handles them with almost no prose damage; vision there wastes money.
Probe interior pages, not page 1 (title pages misread even in clean scans).

### Page markers: every page's text starts with `<!-- page N -->`
The converters write one marker per PDF page (N counts pages in the PDF file from 1, not printed page numbers), so the web reader can put each text page beside its PDF page. Marker-converted files have markers alone on pages with no text layer, so a scan's markdown is not empty: test with `corpus.pages.is_empty()`. Rewriters save through `corpus.pages.write_markdown()`, which refuses a rewrite that loses, adds or reorders markers; if a repair is refused, the repair is what needs fixing. Translation never sends markers to the model: it cuts the text at its markers, translates the pieces and puts the markers back.

### Stub markdown: wrong PDF or image-only body?
A 1-3 KB stub has two causes with different fixes. Wrong PDF (splash/landing page from a fetcher): small file, page count far below the article length; replace the PDF, because vision would OCR the splash page perfectly. Real PDF with image-only body: plausible page count, ~150-300 B/page, cover boilerplate ("This article was downloaded by", "Informa Ltd"); set `vision_ocr_needed`. Both occur in the same batch. Check PDF size and page count against the citation before choosing.

### A partial PDF passes every QC gate; check the section flow
A "first pages + references" excerpt (title, abstract, introduction, one figure caption, acknowledgments, a long reference list, and no systematic section, diagnosis or holotype) passes B/page, the image-only probe and the language audit. For any taxonomic description paper, `grep -iE 'systematic|diagnosis|holotype|description|referred' markdown/{key}.md`; zero hits on a paper whose abstract describes a taxon means re-source the full PDF. A page count short for the journal is a secondary sign.

### Scope-limited vision OCR for whole-volume PDFs
When the PDF is a whole volume but the cited article is a few pages, run `scripts/convert_vision.py --key K --pages "48-49"` rather than the whole file, and leave the PDF intact. Cache entries stay keyed on the true page index, so a later unscoped run cache-hits these pages, and the manifest notes record the scope. The cited page number is rarely the PDF page (cited pp. 39-40 can be PDF pp. 48-49); ask the user for the physical pages.

### Compressing oversized scans
`scripts/pdf_compress.py KEY` re-renders pages to JPEG and steps `max_dim` down until under `--target-mb` (default 90, the LFS soft cap); after the dimension floor it lowers JPEG quality to a floor of 58. Always pass `--keep-source` with a path outside the repository (e.g. `--keep-source ../{key}-full.pdf`), because the source is uncommitted at intake. If a run fails, restore the source backup before re-running; never re-compress an already-compressed output.
Resolution loss costs vision OCR nothing as long as the long edge stays near 1568 px, because `convert_vision.py` caps pages there anyway.
Order: compress, then `intake_acquire.py`, then convert. `intake_acquire.py` rebuilds the acquisition block and drops any `pdf_compression` annotation, so record the compression in the commit message.
A compressed PDF has no text layer: route it to vision, not marker, regardless of year.

### Image-heavy text-layer PDFs: downsample in place, marker the text-identical copy
For an oversized PDF that has a good text layer and many large images (a long thesis with figures at ~1000 dpi over many pages, so splitting out a few big figures does not help), two routes damage it:
- `pdf_compress.py` re-renders pages and destroys the text layer.
- Ghostscript `pdfwrite` with image downsampling keeps a text layer but can break the "Th" ligature ("The" -> "Te", "Thrombolites" -> "Trombolites"). Bag-of-words compare before trusting it; a raw string diff hides this behind harmless `fi` -> `ﬁ` changes.
Downsampling the images in place leaves every page's text byte-identical. PyMuPDF does it (`Document.rewrite_images(dpi_threshold=210, dpi_target=200, quality=82)`, then `save(garbage=1, deflate=True)`; some images nested in form XObjects are skipped). Use `garbage=1`: `garbage=3` merges duplicate font objects, and on a LaTeX PDF that broke the text of 10 of 69 pages (fi/fl ligatures to control codes, en dashes to `\x85`, accents lost); `garbage=0` keeps the old images and grows the file. Compare each page's text with the original's, under both PyMuPDF and pdfium, before keeping the copy, but it is an optional, AGPL-licensed install (`pip install pymupdf`) that the setup does not include. Run marker on that copy, commit the Ghostscript copy for viewing, and say in `acquisition.note` that the committed PDF's own text layer has the ligature fault.

### Marker memory on 16 GB: use --low-memory, kill the workers by PID, split long PDFs
Default batch sizes can take a marker worker to ~20 GB RSS on a 500-page thesis and thrash swap. `convert_marker.py --low-memory` passes small layout/detection/recognition/table batch sizes and `--highres_image_dpi 120`, keeping a worker at ~6-8 GB on ordinary papers. Before any batch, check for a PDF over ~100 pages or an embedded image over ~20 MP; if there is one, use `--low-memory` for the whole batch and give the big PDF its own run.
`pkill -f convert_marker.py` and `pkill -f bin/marker` do not stop marker's workers: they run as `Python -c from multiprocessing...`, get reparented to PID 1 and keep their memory. Find them with `top -o mem` or `ps -axo pid,ppid,etime,command | grep multiprocessing` and kill them by PID. `ps -o rss` can show 0 for a worker; `top -l 1 -o mem` shows the real figure.
`--low-memory` is not always enough, and big pages are not the only cause: born-digital PDFs with many tables (accepted manuscripts, bioRxiv preprints of 50-70 pages) can take a worker past 10 GB within seconds, even with every image removed. Run such keys under a memory watchdog (~9 GB).
Marker's memory grows with the document, so a long PDF that fails whole usually goes through split: cut it into parts of ~60 pages in separate directories, run `marker DIR --output_dir ...` on each in its own process with the usual flags, concatenate in page order, and write the manifest `conversion` block by hand (tool `marker`, notes saying it was chunked). Word recall against the text layer of a joined 470-page dissertation was 0.998. This is free, where vision costs ~$10 per 470 pages; send to vision only what still fails.
`convert_marker.py` copies outputs into `markdown/` only when the whole batch ends, so killing a batch for one bad PDF throws away every paper it had finished. When a batch might be stopped, run one key per process. A PDF that fails when run alone is the cause, not memory built up across the batch.

### PDF compression does not reduce vision tokens; DPI does
Image tokens depend on rendered pixel dimensions (about w×h/750), and `scripts/convert_vision.py` renders at a fixed `--dpi`, so a 0.4 MB and a 25 MB PDF cost the same per page. Compression only blurs the image and, via `pdf_compress.py`, destroys the text layer. 150 dpi is about 2,800 tokens/page, 120 about 1,800 (−36%), 100 about 1,250 (−55%). Keep 150 as default (specimen numbers and diacritics are small text); use `--dpi 120` for plain-prose bulk jobs.

### Local Surya OCR is not a cheaper middle tier
Marker without OCR runs at ~7 s/page; marker `--ocr` (Surya) at over 45 s/page; Sonnet vision at ~9 s/page with concurrency 3. The saving (~$0.018/page) is not worth days of compute on a large backlog, and Surya is worse on old letterpress. Tesseract is lower quality still. The cost levers are DPI and which pages are sent.

## Marker failure modes

### A marker output folder exists from the start of a document, not its end
While `convert_marker.py` runs, `.runtime/tmp/marker_outputs_*/{key}/` is created when marker starts a document; `{key}.md` appears only when it finishes. Count documents as done by the `.md` file, never by the folder.

### Marker can drop a BHL partpdf article page and keep only the attribution page
BHL partpdf exports are article page(s) plus a trailing BHL attribution page. When the article pages have a word-broken text layer (one word per line, common in BZN), marker can drop them and keep only the boilerplate; `intake_qc.py` flags it `likely_stub`. Diagnose by comparing the markdown against per-page pypdfium2 text; fix with `vision_ocr_needed=True` and `scripts/convert_vision.py`.

### Marker can drop the title of an accepted manuscript
When the title sits directly under a bare page number, marker treats it as a running head and the markdown begins at the author line. Every QC gate passes. For a stub-orphan with a blank manifest citation, the markdown title is the only text identifying the paper. After marker on any accepted-manuscript or preprint layout, compare `head -c 200 markdown/{key}.md` with page 1 of the text layer. If the title is missing, prepend it as an H1 copied verbatim from the text layer; re-running marker gives the same result.

### Marker MPS out-of-memory usually means one oversized foldout page
`RuntimeError: MPS backend out of memory ... Tried to allocate 2.72 GiB` in surya's layout encoder is caused by a single oversized page (the layout model still runs under `--disable_ocr`), not cumulative memory. Tell: the same allocation numbers when the key is re-run alone. Probe page sizes (`d[i].get_width()/get_height()` for every page) and look for outliers, such as foldouts three or four times the width of the text pages.
Fix: `TORCH_DEVICE=cpu ./.runtime/venv/bin/python scripts/convert_marker.py --workers 1 --force --key {key}` (a 272-page volume took 8 min). If the OS kills the CPU run for memory (a plate at several times the median page area), copy the full PDF to scratch, `scripts/pdf_extract_pages.py {key} "<ranges without foldouts>" --no-manifest`, convert, then restore the full PDF; record the exclusion in `conversion.notes` and set `page_count` to the converted count. Foldouts are often the correlation chart or locality map, so offer to vision-OCR just those pages afterwards. Do not set `PYTORCH_MPS_HIGH_WATERMARK_RATIO=0.0`.

### Marker reference links swallow the end of the preceding word
Marker opens superscript reference-call links too early: `Zhiluo Formatio[n50,](#page-13-20)`, `Guangdong Provinc[e18.](#page-13-8)`, `Carballido et al[.2](#page-10-0)`. The word becomes unsearchable. `corpus repair ref_links` repairs them, verified against the PDF text layer, which keeps word and call fused as `Province18.`. Run `scripts/clean_ligatures.py` first, since some proposals fail on `ossifcatio`-type words. The author-affiliation form (`Oter[oa]`) is ambiguous and sits behind `--affiliations`, off by default.
Two worse defects are not auto-repairable and need a human reading the page: brackets interleaved through a word (`arya](#page-72-0)n[ska, 1977]` = "Maryanska, 1977") and prose swallowed into link text (`the follo[wing combination o](#page-6-0)`). `--audit` counts both.

### Hundreds of single-letter `<sup>X</sup>` tags mean a broken text layer
Chinese DTP pipelines set Latin text in SimSun fullwidth glyphs and flag every glyph as superscript; marker wraps each letter in `<sup>`, often with degraded spacing underneath. Count with `re.compile(r"<sup>[A-Za-z]</sup>")`:
- over 1000: vision re-OCR (`intake_acquire.py --vision-ocr` + `convert_vision.py --key`).
- 30–500: sporadic font hiccups with correct text underneath; strip `<sup>([A-Za-z])</sup>` → `\1` (digits and multi-character superscripts are untouched).
If the letters under `<sup>` follow English frequency (e t a o i n...), it is full-body pollution.

### Marker can blow one table up into a block of duplicated cells
A ~3 KB table can become 100+ KB, most of the file, with every row the same length and one column replicated into every row with `<br>`. It passes every QC gate (the file is large, not small). Detect with the largest paragraph and its line lengths:
`paras=[p for p in md.split('\n\n') if p.strip()]; big=max(paras,key=len); print(len(big), len(big)/len(md), {len(l) for l in big.split('\n')})`. Identical row lengths are conclusive. Fix by vision re-OCR of the whole key, not by splicing a repaired table into marker output (that leaves `conversion.tool` wrong).
The padding variant (a table that is ~99% whitespace, nothing lost) is handled by `scripts/clean_padded_tables.py`; check the real-character share first. A table that has swallowed prose (a two-column page beside a measured section) loses reading order; splice a vision read of that page.

### Marker can stack two table rows into one and pair values with the wrong specimen
On multi-page tables marker can put two or more rows into each cell with `<br>` ("Centrosaurus<br>Centrosaurus | MP 67.20.29<br>MP 91.18.23<br>RT<br>RT"), split prefixes ("RT" + "MP" for RTMP), and leave the stacked value cells out of line with the stacked specimens. Every specimen number is still somewhere in the file, so a presence check passes; word recall around 0.9 is the only hint. Detector: table cells holding `<br>` in more than one column of the same row. Fix: transcribe the table from the page images one page at a time with a fixed column list, compare per page the multiset of numbers and of words with the text layer (only headers, running heads and page numbers should differ), and splice it over marker's blocks. Marker may also emit the continuation pages' blocks out of order, so locate them by the "Table N. (Continued)" captions rather than assuming one block.

### Character matrices: marker can drop whole taxon rows
Marker can silently drop taxa from a plain-text data matrix in a supplement (including the paper's own new species) while word recall stays near 1.0, because the names survive elsewhere in the file. It can also treat a gap `-` that ends a coding line at a page break as a hyphen and join the lines without it (rows one short), and place a taxon label a line late, moving its codings to the previous taxon.
For any supplement with a matrix, parse the matrix from the text layer (taxon line followed by coding lines; codings may contain `(0&1)`-style polymorphisms and labels need not be binomials, e.g. "EK troodontid (IGM 100/44)"). Check that every taxon is present and every row width matches the declared size (TNT `xread`) or the character count. Fix from the PDF text order: a coding string from the layer that is missing from the whitespace-stripped markdown points at the break. Rows that are short in the PDF too are the source's. If marker's version falls short, replace the section with the text-layer rows (one backticked coding line per taxon) and say so in the file.

### Marker can keep the tables of a bilingual Chinese paper and drop all the Chinese prose
When the Chinese body font has a broken CID map, marker skips those runs while Latin/numeric tables survive. Signs: `likely_stub` at 300–800 B/page, body opens with a table, zero CJK characters, Chinese publisher (DOI 10.3969/j.issn...). There is nothing to translate; route to vision OCR.

### Gutter-numbered accepted manuscripts: marker deletes whole lines
Beyond tabling text (fixed by `clean_gutter_tables.py`), marker runs paragraphs together, hoists headings above their first lines, and deletes whole lines (reference entries, table rows, caption lines). All QC passes, and word counts can exceed the source because surviving tables inflate the file.
Tell: a gap in heading numbering. Measure against the born-digital text layer: strip the page number and the leading gutter number from each line, fingerprint the middle six words, and look for it in the markdown; `corpus qc gutter` does this for every marker-converted manuscript (about 1% of lines is the noise floor). Delete markdown `*` rather than replacing it with a space; verify by hand lines where a gutter number is glued mid-word (`three187`).
Fix: vision re-OCR with `--extra-context` naming the gutter, and `--pages` to skip back plates. `intake_discover.py` detects a line-number gutter in the text layer and hints vision with that context. Against marker's output, what marker has that vision lacks is noise (link fragments, words split at hyphens or glued together).
Manuscript-style supplements have the same gutter, so check every supplement for line numbers before running marker. On one, marker kept every word but shifted the reference column of a table by one row for three taxa and turned 72.1 into "72."; word recall cannot see this, so compare table rows against the text layer and check column placement on the page image. `convert_vision.py` has no `--supplementary` flag; set `V.PDF_DIR`/`V.MD_DIR` to the supplementary dirs and call `ocr_one_pdf(..., {stem: {}}, stem, log, extra_context)`.
`corpus convert recover` (`convert_recover.py`) takes no extra context, so pages it recovers transcribe the line numbers; strip them afterwards.

### Science/Nature reprints carry neighbouring articles
Single-article reprint PDFs bundle the tail of the preceding and the head of the following article, and marker interleaves them. It is fluent English, so `intake_qc.py` and `qc_languages.py` pass it. `scripts/qc_spillover.py` reports such files (default scope Nature/Science plus orphan keys; `--chapters` adds book chapters, where section headings and translated titles make it noisy). The tell is a title-like heading that is not the paper's own; one "Received … accepted" line per Nature letter and one reference heading per paper are the supporting counts. Nature prints a "Correspondence and requests … addressed to" line only from about 1997, and Science never, so that line cannot be relied on as the end marker. Shared-page book entries (encyclopedia `*see*` stubs, items printed between the halves of a reference list joined by "Continued on p. N") and journal title or contents pages in front of a paper are the same fault.
Trimming: `corpus clean spillover --key K` (dry run; `--apply` writes) trims a Nature letter whose Correspondence line is addressed to one of its authors, and refuses anything else; page markers stay. Otherwise trim by hand: target = own title heading to the next article's title heading (or EOF). Check by counting the paper's genera plus "dinosaur"/"theropod" outside the span (0, or 1 where a cover sheet repeats the title) and by reading the 90 characters each side of both cuts; slice with asserts; record the kept offsets and what was cut in `conversion.notes`. Science PDFs from the publisher site carry a download cover sheet for the same paper before the title (occasionally after); it holds no body text and goes with the trim. Vision-converted files keep the neighbours in `.runtime/cache/vision/{key}/`, so a vision re-run brings them back.
Before trimming a cited key, check that no dataset quotation sits in the text being removed. Not spillover: two reference headings caused by a bad blocked-page recovery (see "Content-filter recovery" below), and a symposium abstracts page kept as the abstract's bibliographic context.

### Detached diacritics corrupt two words, and accent-insensitive search fixes only one
Marker sometimes strips a combining mark and re-emits it a few words later: "the La Pena, ... and Quebrada ˜ de la Sal members", where `La Peña` lost its tilde and `Quebrada de la Sal` gained one. NFKD accent folding finds `La Pena` but still misses `Quebrada ˜ de la Sal`, because the fault there is an extra character. Other examples: `Pal ¨ aontolo- gie`, `Pos-Graduaç ao em ˜`, `Cern ˇ ý`. It occurs hundreds of times across dozens of files in a large corpus.
When a name with a diacritic returns zero hits, search the stripped form, a form with a stray mark spliced in, and a wildcard across the phrase.

### Dense occurrence tables: read the markdown, never the text layer, and check odd rows
Marker (1.10.2) separates the columns of dense occurrence tables (*Dinosauria* 2nd ed.) far better than `get_text()`, which interleaves them line by line and invents strings like "Clarens Formation (Free Pliensbachian". Marker isn't perfect and can splice a row ("Kalazha Formation (Xinjiang Tithonian<br>Uygur Zizhiqu)"). Detector: `[A-Z][a-z]+\s+\([A-Z][a-z]*\s*(Hettangian|...|Rhaetian)`; across ~900 pages of such tables it gives about one true hit and one false positive. On the text layer, phrases like "Bushveld Sandstone" are split by newlines, so search a whitespace-collapsed view.

### Stay on marker-pdf 1.10.2; test any upgrade on occurrence tables
marker 2.0.0 is 8-14× faster and fixes the MPS worker bug (workers=2 output byte-identical), but it corrupts dense occurrence tables: it re-interleaves columns and joins ages onto place names, giving several times as many splices as 1.10.2 under the detector above. `--mode balanced` is worse. It fixes neither the stolen reference-link letters nor the dropped spaces. Use the occurrence-table splice detector as the acceptance test for any upgrade; the bar is 1.10.2's result, not zero. Measurement traps: raw byte counts mislead because 1.10.2 pads table cells heavily, so compare non-whitespace content; a rising distinct-word count can mean spaces have collapsed, so count 22+ letter tokens separately.

## Text-layer font defects: repair mechanically, not by re-OCR

### Elsevier font AdvPS44A44B: en dash extracts as "e", em dash as "d"
This dash-only subset font has no `/Encoding /Differences`, so dashes come out as letters: `BarremianeEarly Aptian` (en dash), `CheloniadPodocnemidoidea` (em dash). The em-dash form is the dangerous one because it yields a plausible single word. The fault is in the PDF's text layer, so neither marker nor re-OCR fixes it. `corpus repair dash` repairs it; it runs on every intake batch as part of `corpus repair all` (step 9a of `/intake`). Never fix this with a regex on the markdown: `[a-z]e[A-Z]` matches `ScienceDirect`, and no regex can see the `d` form. The repair keys on the font, replaces whole whitespace-delimited tokens, and has a second pass for bibliography ranges marker turned into links (`25 e[125]`); the dry run prints those edits marked "split by markup". Occurrences at other codes are left for review (`$` = ×, `!` = ~, `C`/`D` = ° and δ). Sibling fonts: `AdvPS3FDD77` (`(` = °, `#` = ′) and `AdvP4C4E74` (`¼` = =, `þ` = +).

### "€" for the umlaut: T&F/Wiley/Elsevier fonts extract the diaeresis as the euro sign
Some publisher fonts map the diaeresis glyph to "€", and marker passes it through, either before its vowel ("M€uller", "f€ur", "pro€otic") or detached ("Lu, J. €", "Eotv € os", "Follmi, € 2012", "Pal € €aontologie"). `corpus repair diaeresis --all [--apply]` reads the fix from the PDF by glyph position: each "€" is drawn over its vowel, the vowel is the letter under the mark's centre, and the word is read off that line by x, a word ending where the gap exceeds 0.15 × font size. That gives the map entry (Hubner -> Hübner); in the markdown it removes a "€" only when the word it sits in, the word it splits ("Eotv € os"), or a mapped word within 12 characters can be umlauted, and touches only the repair site. Dry-run invariant: strip diacritics, "€" and whitespace, and old == new.
Left for review: "€" that marker wrote for an acute accent, which the PDF encodes as a control character ("Lor\x01and" = Loránd, markdown "Lor € and"), and marks inside Elsevier reference-link markup where marker broke the word across link brackets. Real euro signs are untouched (no vowel under them). "€" in `GlyphLessFont` (the invisible OCR layer on scans) is skipped: it is OCR noise, and mapping it umlauts scans at random ("thë", "Äfter", "THRÖUGH"). Some umlauts are faithful to print, including a journal's own misprint ("Sänchez") and "troödont".
The same PDFs encode other accents as control characters before the vowel (\x01 acute in most fonts; \x02, \x03, \x13 vary by font: "Sebasti\x01an", "Mus\x02ee", "M\x13arquez"); marker usually drops these, so the markdown shows the bare letter.
It runs on each intake batch as part of `corpus repair all`, like the dash repair.

### Dropped f- and Th-ligatures: scripts/clean_ligatures.py, gated on word frequencies
Some born-digital PDFs decode every f-ligature as a bare "f" ("frst", "signifcant", "shaf", "lef"); the capital Th ligature becomes "T" ("Te Bauru Basin", "Teropoda"). The fault is in the PDF, so a marker re-run does nothing. The script only inserts letters after an existing f. Usage: `--scan` (census), `--audit` (corpus-wide dry run; read it before any bulk apply), `--key`/`--path`, `--apply` (writes `.ligature.bak`). `--all --apply` skips `*.original.md`. Verify a sweep with `git diff --numstat`: added and removed line counts must match. Re-index after applying.
Lexicon: `--lexicon corpus|wordfreq|auto`. Corpus mode uses word counts from clean corpus files (cached at `.runtime/cache/ligature_lexicon.json`) and requires a repair to win by 10× where both spellings occur. A small corpus has too few clean files for that, so below 500 clean files `auto` uses `wordfreq` frequencies in the paper's language and English, plus a domain vocabulary from the data repo's public data (bib authors and titles, taxon names and descriptions). On a large corpus the two modes agree on almost every repair, and wordfreq mode also makes real repairs corpus mode refuses (fattened→flattened, refect→reflect, Tanks→Thanks).
Rules for any such gate, each learned from a wrong repair:
- `/usr/share/dict/words` can't be the gate: it lacks "feet" and "floodplain", and a dictionary gate rewrites feet→fleet throughout.
- No entry in a "break signature" list may be a real word in any corpus language ("diferente" is Spanish, "Tese" Portuguese).
- The data repo's descriptions contain broken forms themselves ("lef", "afer", "difcult"), so domain words may vouch for a repair but never protect a token as written. Genus and clade names may protect: `Fona herzogae` is not Fiona.
- A capitalised word mid-sentence is protected by any language (Eifel is German, Flament French) and repaired only to a bib name (Bufetaut→Buffetaut) or a very common word (Lef tibia→Left); otherwise Defant→Defiant. A sentence-initial capital is an ordinary word, but not after an initial ("E. Markgraf").
- No "i" appended at a word's end: that makes Latin epithets (Markgraf→markgrafi).
- In the Th path, count lowercase tokens only: the fault is capital-only, and broken "Tis" can outvote "this".
- An ASCII fragment beside a non-ASCII letter or a spacing accent is judged as the whole word: "geográfca"→"geográfica", but never Lefèvre→"Leftèvre" or "Pa´lfy"→"Pa´lffy".
- Missing spaces (`KaiparowitsFormation`, `theAguja`) are the mirror defect: `corpus clean glued-words` (`clean_glued_words.py`, `--scan` for a census) adds spaces only, by the same document frequencies. `corpus.lexicon.document_frequencies` builds such a lexicon for any repair.
  Read the dry run before `--apply`, and not only the splits that produce rare words: on a LaTeX PDF whose whole text layer lacked spaces it also split names into ordinary English words (`Moopen` to `Moo pen`, `Bulletin de` to `Bul let inde`, `discretionary` to `disc ret ion ary`) and cut genus names at a common prefix (`Plate osaurus`, `Mus saurus`). After applying, list adjacent pairs that the PDF's text layer prints joined and check each.
- For any repair that uses the corpus as its lexicon: build the lexicon excluding files that show the defect (else the defect protects itself), ban one-letter right halves (Latin endings), supply weights for "a"/"I", and add a document-level gate as well as per-token gates.

### Ligature repair: read the dry run for abbreviations, names and other languages
Forms the dry run proposes that must stay as written:
- figure-legend abbreviations: `fco` fibular condyle, `frm` foramen, `sof` suborbital flange, `afn`, `fna`, `Classif.`;
- place names and other languages: the Moroccan `Rif` (not Rift), German `Fach`, `Feld` ("Im Neuenheimer Feld"), the facies code `Fle`, Spanish split by a space or OCR (`ofre ció`, `mam- ´fero`, `í feros`);
- authors and quoted misspellings: `Foresi et al.`, `*Phytosaurus kapfi* [*sic*]`;
- garbled text where no repair is right: `3-5 flm` (µm), `昀椀fth`, `sh<br>rif<br>he`.
Run it twice: the lexicon changes as papers become clean.

### Nature Adv* fonts read fi/fl/en dash as ®/¯/±
Late-1990s/2000s Nature PDFs (e.g. `AdvPS81DB`) have an empty /Differences encoding, so `signi®cant`, `¯ow` and `north±south` come straight from the text layer; `corpus repair symbols` can't fix this, `corpus clean ligature-codes` (`clean_ligature_codes.py`, `--report` to classify first) does. A repair must require at least three ligature glyphs next to letters in the file, because a spacing macron looks identical (`Ky¯ory¯ugaku`); don't lower that threshold without adding a dictionary gate. A real ± has a space on both sides. Files with mostly free-standing ®/¯ have a different defect.

### Dropped symbol glyphs: restore by (font family, glyph name), never glyph name alone
Subsetted symbol fonts (Elsevier `AdvP4C4E*`, `Universal-*Pi`, `MathematicalPi-*`, `Symbol`) extract °, ′, ″, ±, ×, ≤, ≥, ~, en dashes and accents as C0 control characters; marker drops them: `(79°32′, 19°15′)` -> `(7932, 1915)`, `~200 Ma` -> `200 Ma`. No QC detects it.
`corpus repair symbols --all --apply` reads each font's `/Encoding /Differences`. For control characters it cannot place, `corpus qc control-glyphs --scan` lists every (font, code) pair in the corpus, `--sheet` renders a crop of each, and `--expand READINGS` turns one reading per font into the per-paper map that `corpus repair control_glyphs --map-file` takes. `C##` names are subset-internal: `C21` is a breve in `AdvP4C4E59` and `≥` in `AdvP4C4E74`, and keying on the name alone writes `Rusca Montan≥` throughout a paper. Verify every new mapping against a ~400 dpi crop.
Accents: `corpus repair accents` identifies the base letter by geometry (the mark's box overlaps its own letter by at least half the mark's width, and its neighbours by about nothing). Marker renders a dropped accent three ways (absent, a space, or a wrong stray mark like `Universit ~ aria`), and the code-to-accent mapping is per subset, so each key needs its codes read off crops.
Some fonts also extract a hyphen as "2" (Vertebrata PalAsiatica) or as 鄄 (some Chinese journals); these look like OCR damage but come from the text layer.

### Locality coordinates lose °/′/″ three ways; only the rendered page tells which
No QC catches a damaged coordinate, because it reads as a clean number.
1. Substitution: subsetted symbol fonts reuse digit glyph names for °/′/″, and `/Differences` corroborates the lie (`AdvP7DA6` prime = `/nine`, `AdvPi1` degree = `/eight`). `25°28′15″N` becomes `258 28<sup>0</sup> 15<sup>00</sup> N`. Recurring: `AdvP4C4E74 '0'` = ′ (doubled = ″), `AdvPi1 '8'` = °, `ESSTIX-Four '(' '#'` = ° ′.
2. Dropped primes: marker keeps ° (as `◦`) but drops ′ and ″ from maths fonts (`MTSY`). The PDF text layer still has them; diff against it instead of re-OCRing.
3. Scan OCR reading ° as `0`, `'`, `"`, `?`, `•` or the word `go`.
To find candidates, look for a character in a coordinate whose font differs from the run's dominant font, and render a 400-dpi crop: `corpus qc symbol-glyphs --key K --crops DIR` does both. To find coordinates, require a latitude and a longitude token together (one hemisphere letter alone gives about ten times the hits). Some papers print no degree sign at all: the markdown is faithful, leave it. `corpus clean coordinates --audit` lists suspect coordinates; record each verified reading as a before/after pair in `repairs/coordinate_glyphs.json` (`{key: [[before, after]]}`) and apply them with `corpus clean coordinates --apply`, which skips a pair that does not match exactly once.

### Elsevier transposed/spacing accents: fix mechanically, never by vision
Older Elsevier text layers encode accents as base + spacing glyph (`Neuque´n`, `Rı´o`, `Man˜ero`), sometimes with no composed accent in the whole file. The mark can precede or follow its base (`Mus´eum`, `S˜ao`), so a repair must decide by which letter can legally carry the mark, then by the file's own majority: `corpus clean transposed-accents` (`clean_transposed_accents.py`; `--audit` lists the word changes corpus-wide, `--fix-miscomposed` repairs `Rodŕıguez`-style damage from treating every mark as following its letter). For marks that only ever follow their letter (`Osmo´lska`, `Lu¨`), `corpus clean diacritics` (`clean_diacritics.py`) folds them and refuses a whole file where `~` and `^` are misread letters of a rough scan (`--list-flagged`). Guards: ASCII `~`/`^` are prose ("~150 km"), backticks are code fences, coordinate minutes (`38°55´S`) need no letter before. Fixing accents can push langdetect over the translation threshold on English papers: check function-word counts and record `translate_skip` with a note.

### ASCII-looking OCR garbage: `corpus qc garbage`
Bad scan OCR emits plausible ASCII (`agili8`, `Ankylo8aurus`, `'1'he` for The), which the PUA/U+FFFD scan cannot see. `corpus qc garbage` scores digits fused into words and 19th-century scan signatures per 1000 tokens (flag: 3 and 1.5), and with `--near-miss` letter misreads with no digit (`Ornlthlschia`). It only nominates: anatomical labels such as `Cv1` and proper names score too, so read the printed tokens before re-OCRing.

### CID-garbage detector: short letter runs >45% AND letter fraction <55%
Broken font CID mapping replaces body text with plausible ASCII gibberish. `qc_scan.py` (fires on PUA/U+FFFD only) and `intake_qc.py` (bytes/page) both miss it. Detector: strip `<br>` and URLs; short-run fraction = runs of `[A-Za-z]` with length ≤2 over all runs, flag if >45%; letter fraction = letters/chars, flag if <55%; skip files >2% CJK. Token density is the wrong metric (most of its hits are tables and reference lists). For scale: a garbled file scored 72.8% / 8.8%, the same file after vision 24.9% / 74.4%, against a corpus median of 21.6% / 73.8%.
Triage a hit with word recall: take every 8+-letter word in the PDF text layer and count how many appear in the markdown. Recall near 4% means the prose is destroyed (re-convert); near 96% means the prose is intact and only tables are shredded (leave it). Table explosion shreds tables but keeps sentences; CID garbage destroys prose. Check recall before telling anyone a file blocks work.
Recall checks prose only. If the answer lives in a figure or chart on an image-only page, the PDF is the source regardless of the markdown score.
A zero count for a word in the paper's own title is the human-visible tell.

### Fullwidth Latin in Chinese journals: finding affected files
CLAUDE.md covers the cause and fix (vision re-OCR). To find cases corpus-wide, a "long space-free run" scan gives hundreds of false positives (`infrapostzygapophyseal`, `Naturwissenschaftliche`). Require ≥50 co-occurring CJK characters and runs ≥30 characters (real long words cap near 22). To check a text layer, NFKC-normalise first or count characters in U+FF01-FF5E. After repair, only fullwidth punctuation should remain. Re-OCR can newly surface a translation candidate.

## Reading PDFs with pypdfium2 (`corpus.pdf.text`)

Scripts read PDFs through `corpus.pdf.text` (`PDF_BACKEND=pdfium`, the default; `pymupdf` is selectable for comparison), write image-only PDFs through `corpus.pdf.build` (img2pdf + pikepdf), and copy pages with pypdfium2's `import_pages`. What a script author needs to know about pdfium:

- **Character boxes and sizes.** Use the *loose* box (`FPDFText_GetLooseCharBox`: font ascent to descent, advance width); the default `GetCharBox` hugs the ink. `FPDFText_GetFontSize` is the size before the text matrix (often 1.0): multiply by the matrix scale. Type 3 glyphs have a near-zero loose box; the helper falls back to the ink box.
- **Reading order around accents.** pdfium does not keep separately drawn accent glyphs next to their letter: it collects them elsewhere (another line, with generated spaces around them) and starts a new line at the font change ("Prieto-M\x01" / "arquez"). Anything that reads the mark from text order breaks. The helper moves spacing marks back over their letter and drops generated line breaks between glyphs that touch on one visual line; find a mark's letter by geometry (overlap at least half the mark's width).
- **Spaces.** pdfium's spaces are generated (inferred from gaps) and take the font of the text before them; they can sit between two touching letters where a foreign glyph was in text order. Font tallies and word building should ignore spaces.
- **Font names.** pdfium gives them in full (`Universal-GreekwithMathPi`), and none for Type 3 fonts. `FPDFFont_GetFontName` returns the substituted system font (Arial for Helvetica): use per-character `FPDFText_GetFontInfo`.
- **Ligatures.** pdfium expands ﬁ/ﬂ into separate letters.
- **Unmapped characters.** pdfium returns code 0; the helper reports U+FFFD.
- **Page lines.** pdfium keeps a page number and running head on the same visual line together.
- **Font /Differences tables** are read with pikepdf (`corpus.pdf.text.font_differences`). Pages inherit `/Resources` from the page tree (`Page.resources` follows it); never de-duplicate direct pikepdf objects by `id()`, which repeats. `/Differences` can be stored as a separate indirect object, which a regex over the raw PDF misses.
- **Stitched page size.** `corpus.pdf.build` uses an image's DPI, else 96; it uses 72 DPI for every JP2 and for declared DPI below 10. JPEG and JP2 data go in byte for byte.
- **Image extraction.** pdfium decodes 1-bit fax scans to RGB; `pdf_images.py` writes them back at the source depth (1-bit PNG). Files are named `p{page}-i{n}`, since pdfium has no object numbers.

### Superscript reference calls: what `corpus repair fused_calls` refuses
Raised digits that are not calls must stay as written. The script measures "raised" on horizontal lines only (rotated table headers make subscripts look raised), compares the call's baseline with the last glyph of the word before it (a span can open on a raised character, "Z. FOREMAN2"; a lower glyph elsewhere on the line, such as a symbol-font "=", must not count), requires the call to start past the word's middle (a kerned hair space can overlap "Hattori1,2"), merges a call split over touching small spans, and refuses:
- chemical formulas and ions (CO2, SiO2, Ca2+, a charge sign after the digits);
- exponents (no call starts with 0 or precedes a decimal point: "body mass<sup>0</sup>.75");
- isotope mass numbers ("Ar40/Ar39", "87Sr/86Sr", "Nd143": an element symbol with a number in its mass range, 1.8–2.7 × Z);
- anything next to a slash or hyphened to a word (specimen "BENC32/2–0001", land-survey "SE1/4").
A PDF word must match a whole markdown token that ends the call, so "deinonychosaurs6,11" is never cut to "<sup>6</sup>,11". Matching has fallbacks for how pdfium's text differs from marker's: two or three letter runs joined (kerned capitals), accent marks removed ("Ro´gers"), missing word spaces ("andFernandoEscaso"), and the call with the markdown's spaces or only its first group. Applied edits only add `<sup>` tags, so stripping them must give the old text exactly. Known misses: units whose minus extracts as "2" ("km3 yr21"), superior-figure glyphs set on the body baseline, and author names in rotated text.

## Scan OCR damage

### Two OCRs disagree on a digit: render the page, don't vote
Both can be wrong on the same glyph, and overall text-layer quality says nothing about a given token. Vision can read 330 and an archive text layer 550 where the page reads 350 (old faces cut 5 with a flat top bar and 3 with a rounded bowl; on soft scans they converge); an otherwise-garbage text layer can be right where vision is wrong.
Render the number at 14-16× on a tight clip beside an undisputed digit from the same page, stacking all disputed crops into one strip; for a quick look, `d[PAGE-1].render(scale=4).to_pil().crop(...)` and Read the PNG. Narrow the question first ("is the fourth tooth V235?") so one page can answer it, and leave room for an answer outside your hypotheses. Record the repair where a re-conversion will not lose it; for a translated key, write the rule to match both source-language and translated wording (the chain is convert -> repair -> translate).

### One letter pair can fail 100% on an otherwise clean scan; repair it in place
A scan can read cleanly except for one capital pair: "Turney Ranch Formation" wrong every time in many different misreads (`Tlirney`, `Turaey`, `T\irney`, `TVirney`, `Tbrney`), so the name is invisible to search.
Test: count how often the proper noun is right in the same file. Zero correct plus several different spellings means one glyph pair failed. Check the same pair elsewhere in the file, confirm the damage is in the PDF text layer, then repair the enumerated variants with a context-gated regex (`\S+(?=\s+Ranch)`) rather than re-OCRing (vision on a clean scan risks fabrication). Do not sweep the corpus on the misread strings: "irney" also matches the surname "Birney".

### Scan OCR reads lowercase l as "/"
Some scans (paleoarchive.com Uppsala Bulletin) give `Euhe/opus`, `Te/eosaurus`, `Pa/aeontol.`, `Vertebrata Pa/Asiatica` dozens of times in a file. This passes every QC gate but breaks FTS. Detect per key: `grep -oE '[A-Za-z][A-Za-z.]*/[A-Za-z][A-Za-z.]*' | sort | uniq -c`; read the token list, allowlist real slashes (`and/or`, `kg/day`, `Jinlingshen/Yewangzhuang`, specimen numbers like `MPC-D 100/764`), replace the rest, and loop (two faults per word need two passes). Not `scripts/clean_despace.py` (it only removes spaces, and false-positives on German: `und am`→`undam`). Sibling misreads in the same scans: `MA TEER`, `Mclntosh`, `Vol. Il`→`Vol. 11`, accession stamps over the title line (restore the title from the citation).

### Old USGS Professional Paper scans misread capital R as E, K or B
In mid-century USGS Professional Paper scans 11–25% of "Ripley" can read as Eipley/Kipley/Bipley (plus Eiver, Eidge, Kecent). Lowercase r is fine and the prose is otherwise clean, so marker plus a whole-word repair beats vision. Find candidates by listing E/K/B-initial non-dictionary words that become words with R; read them in context first (Keownville and "Key and Biddle" are real). Check the unit name's count before and after.

### Foreign scan with clean prose but garbled structure: hand-clean, then translate
On rough pre-WWII foreign scans (e.g. German Palaeontographica) marker can give clean running prose with thousands of umlauts while the contents, captions and notation are garbled: ° read as trailing `0` (`45-500` for 45-50°), ½ as `l/,`, specimen numbers split (`dd 11 1`), captions interleaved into prose.
Such a paper can evade `qc_languages.py` (langdetect returns unknown), so "no language flag" does not mean English: count diacritics directly (`re.findall(r'[äöüßÄÖÜ]', md)`).
Fix: conservative cleanup of named artifact classes only (rebuild the contents, ° in angle contexts, fractions, specimen-number spacing, de-interleave captions; never touch prose, leave ambiguous cases), then `convert_translate.py`. This is cheaper than vision re-OCR of prose that is already clean. The user prefers a QC checkpoint before translating rough scans.

### German *gesperrt*: two different failures
German journals (Neues Jahrbuch, Palaeontographica, ZDGG) letterspace the systematic labels (`H o l o t y p e :`). (1) Bad scan OCR garbles letters and spacing (`Hoi 0 t y p e`, `o`->`0`): vision re-OCR fixes the letters. (2) The spacing is real typography, which vision reproduces faithfully: rejoin it afterwards with `corpus clean gesperrt --key K` (`clean_gesperrt.py`: space-deleting, all-or-nothing, dictionary-segmented), then normalise `^Label\s+:` to `^Label:`. `clean_despace.py` cannot help, since every token is a single letter.
A dictionary-gated rejoin mis-segments letterspaced species epithets into common words: `p r o r i g e r` -> `pro rig er` (should be *proriger*). Letterspacing is how 19th-century journals set new names, so the damage lands on the most important words and nothing flags it. Read the dry-run list; a rejoin into 2-3 short common words is the tell. Fix taxon names by hand, and check first whether vision already de-letterspaced the text.

### clean_despace.py guard details
Beyond the CLAUDE.md description: `--apply` writes a `.despace.bak` before the atomic write. Guards block false merges across abbreviations ("see p."), units ("5 m in"), initials, split proper nouns ("the N odosauridae"), and three-token ambiguity ("for th e" → "for the", not "forth e"). A deny set plus a length gate of ≥5 characters (or a safe-short list) stops short words left over from line breaks. Splits where both halves are real words ("for amen" for "foramen") are left alone.

### Italic z with a descender reads as x
In the italic of early-1900s German antiqua (Gustav Fischer, Jena), z has a descending tail and looks like x at normal resolution. Vision and the scan's own OCR can both read *polyzelus* as "polyxelus", so agreement between the two proves nothing here. Settle it by cropping every occurrence at scale 6-10 using the text layer's character boxes and comparing the glyphs side by side; then fix the vision cache and the markdown together, before translating. Expect it in italic species names containing z (*polyzelus*, *zitteli*, *franzi*).

## Vision OCR

### Vision fabricates plausible tokens and normalises spellings
On poor scans Sonnet sometimes writes a name carried over from nearby context instead of `[ILLEGIBLE]` (a heading for one species came out as a different, related binomial). Clean scans also misread epithets while specimen numbers are right. Checks: verify headings, the genus each page describes, and specimen numbers against a render at scale ≥5; grep a new binomial against the corpus (`grep -rho 'sinojap[ao]norum' markdown/*.md | sort | uniq -c`). Fix both `markdown/{key}.md` and the page's cache JSON, or the next cache hit restores the error. When a translated key has a wrong name, diff `.original.md` against the vision cache before blaming the translator.
Vision also "corrects" historical spellings to modern forms (Trionycididae → Trionygidae, Cheloniadae → Cheloniidae in an 1850 work) and normalises wording ("dinosaurian" → "dinosaur"). Where original spellings matter (nomenclature, synonymy lists, pre-1900 works), compare the set of capitalised names in the vision text with the set in the text layer and read every mismatch on the image.

### A born-digital CJK text layer is a full control for vision OCR
Where marker keeps only the tables of a Chinese paper, vision is the conversion, but the born-digital text layer is still correct. `scripts/qc_textlayer.py` aligns them; on CJK pages it finds substitutions that change the anatomy (锄骨 vomer→颧骨 jugal, 肱骨 humerus→胫骨 tibia, 粗短 stout→细短 slender), formation names and author surnames, and eye-skips between repeated phrases that drop a sentence and print another twice. `scripts/repair_cjk.py` proposes the corrections, including a dash printed between two characters (中—晚期) read as 一 'one'. Apply small edits only where the context matches exactly, fix table cells by hand (cell order differs between the two), then re-translate. Reject layer typos (广范), variant forms (緑, 內), running heads, broken-font glyphs (鄄; 方方土 for 坤); 足庶 for 蹠, metatarsal, where vision reads 趾 'digit' instead and turns metatarsal tables into phalanx tables, so write 蹠 by hand and pairs aligned against different sentences or table cells. Some layers are no control at all: ciphered fonts (digits come out as `$"%`) mean checking on the image.
The same audit finds pages vision returned empty or cut short in any language: look for cache pages with `output_tokens` under ~50 on a page whose text layer is long. Correlation-chart pages get only a description from the general prompt; transcribe those in vertical strips at high resolution with a chart prompt and label the result.

### Verify vision OCR against the garbled text layer's number multiset
Bad OCR mangles letters far more than digits, so the text layer you are replacing is still a control. Extract the catalogue-number pattern (tune the regex to the series) from the raw text layer and from the vision markdown and diff the Counters: text-layer-only = dropped content; vision-only = fabrication or a caption the layer shredded (look at the page).

### Image-only scan with no text layer: diff vision against tesseract word counts to find eye-skips
When there is no text layer to use as a control, make one: render each page at scale 3, run `tesseract page.png - --psm 1`, and diff `Counter`s of `[A-Za-zÀ-ÿ]{5,}|\b\d{2,5}\b` per page (join `-\n` first). Tesseract-only words that are real words, not its own misreads, mark text vision dropped; vision-only words are mostly its `[FIGURE: …]` descriptions and restored diacritics. A spot-check of the taxon pages can pass while vision has skipped between repeated strings: one citation attached to the wrong genus, a 40-word passage with a measurement lost between two identical "et al., this volume" references. A vision-only specimen number is not proof of fabrication (it may be printed two lines below tesseract's nearby sentence); read the page before deleting.

### A second model's reading is a cheap check, not an answer
Re-reading pages with a newer model and diffing the two readings page by page finds misreads: the newer one can fix systematic i/l errors in taxon names (*Lufengla*, *Yunnanla*, *Dinnetherlum*, *Bienotheroldes*) and introduce errors of its own that only the page image and tesseract settle ("Sues, 1986a" read as "Sues, 1985"; "Olson" pulled to "Olsen" by a misprint in the heading above it). Where the two disagree, the newer reading is not automatically right.

### Content-filter recovery: `corpus convert recover`, cut only on whitespace
`corpus convert recover --key K --page N` (`scripts/convert_recover.py`), then the same with `--apply`. It tries the intact page, then cuts only where there is no text: a two-column page at its gutter (a band is full-width only where ink crosses the gutter), and any region that still blocks at the blank row nearest its middle, to depth 5. Pieces never overlap, so nothing is stitched or duplicated. It accepts a page that is still a `[VISION OCR FAILED ...]` line, so it is the first and only recovery step. The first run saves a candidate and prints measurements only, never page text; `--apply` writes the page and a cache entry so a later `convert vision` run reuses it.
- Blocks are reproducible per page and on every model tried; adding "this is a peer-reviewed scientific paper" to the prompt does not help. The pieces pass.
- Single-column pages: pass `--columns 1`; it reads them from pieces cut on blank rows, and word counts come within 1-2% of the text layer.
- A strip holding only a running head or white space comes back as a remark about the image ("No body text is visible in this fragment…"), or as the model's reasoning (`<think>The image is essentially blank…</think>`). The script drops both; grep any hand-run piece for "fragment".
- A cut between pieces can leave a sentence split across two paragraphs when the second piece starts with a capital or a bracket ("in the Middle" / "Jurassic of China"); join those when you see them.
- Known limit: ink that crosses the gutter partway down (a figure edge, a stray mark) starts a full-width band there, which cuts both columns and yields left-top, right-top, left-bottom, right-bottom, so a right-column block can land inside the left column. Fix those by hand. The order score below catches a large swap; a swap of a few lines can fall inside its 0.03 tolerance. A rule keeping a band full-width only if its ink reaches well into both columns would also split full-width figure captions whose word gaps stop the reach.
- If recovering by hand instead, save a synthetic cache entry at `.runtime/cache/vision/{key}/page-NNNN.json`, or the next `convert_vision.py` run re-blocks and overwrites the recovered text with a FAILED marker.

Score a candidate against the PDF text layer, or tesseract where there is none, with two numbers on 4+-letter words: recall (multiset overlap / reference words) and in-order coverage (`SequenceMatcher` matching blocks / reference words). A correctly ordered page has in-order equal to recall; pages with paragraphs out of order score 0.54–0.82 in-order against 0.85–1.00 recall. Word count over reference above about 1.1 means duplication. A repeated-substring test alone misses out-of-order text, and two acknowledgements or reference headings are not a defect by themselves (a page can hold both); check their order.

### Map recovered pages by the cache string, not by splitting on `---`
Page text can contain its own `---` rule, so splitting `markdown/{key}.md` on `"\n\n---\n\n"` gives more segments than pages and shifts every index; a check then runs on the wrong text and reports clean. Locate each page by its cache JSON `markdown` value, `assert md.count(t) == 1`, splice back by value with `md.replace(t, cleaned)`, and rewrite the cache entry. Sanity-check first: segment count against PDF page count.

### convert_vision.py silently skips already-vision keys
Without `--key`, `select_backlog()` excludes keys whose `conversion.tool` is already `claude-vision` even when `vision_ocr_needed=True`. For a replacement re-OCR (new PDF, or after `/extract-pages`), pass `--key K` explicitly, and check the "Vision-OCR candidates: N" count against the keys you expected. Clear `.runtime/cache/vision/{key}/` first (or pass `--force`), since the cache key does not include page content.

### Appending pages to an already-converted key: append at the END
If the existing pages are cached and the new pages are appended at the end of the PDF, merge the PDFs (`scripts/pdf_append_pages.py`) and run plain `convert_vision.py --key {key}`: pages 1..N cache-hit and only the new ones cost anything. Inserting pages in the middle shifts every later index and invalidates the cache.
Do not use `--pages` for this: the script builds the markdown from only the selected pages and atomically overwrites `markdown/{key}.md`, so `--pages 85-89` would replace an 84-page conversion with 5 pages. Read a script's write site before trusting a scoping flag to be additive.
For a translated key, the new chunk must also be appended to `{key}.original.md` and translated separately into `{key}.md`. Update `acquisition.pdf_extract_pages` to the combined range (e.g. `"58-92, 145-147"`).

### Rebuilding markdown from the page cache reverts cleanup
Regenerating markdown from the raw per-page cache reverts `clean_frontmatter.py` and `clean_running_heads.py`. Run those last, after the final rebuild, and check for `markdown/{key}.original.md` before rebuilding a translated key. `clean_running_heads.py` is unusable on index-heavy books (it wants to cut thousands of index lines); remove real running heads by hand there.

### Conference posters: hand-repair after `scripts/convert_poster.py`
Always `--dry-run` first to check the tiling plan and DOWNSCALED flags. If only the two outer margins are detected as gutters, the title banner is masking them (`--top-frac`, default 0.08). Two artifacts always need hand repair: the title fragments across title tiles and must be reassembled from the pieces, and a heading in a row-overlap band is transcribed twice (`sort file | uniq -d` finds it). Verify against the rendered image. Key posters as `{author}{year}z`.

### Vision adds series digits to Chinese unit symbols
Chinese stratigraphy papers print formation symbols as K or J with a subscript letter only, e.g. 茅店组(K<sub>m</sub>), 周田组(K<sub>z</sub>). Vision OCR "normalises" them to series-digit forms (K₂m, K₁l) and reads a subscript z as 2 (K₂), which turns a lithostratigraphic symbol into an age claim the paper doesn't make. In these papers, check every unit symbol against the page and write subscript letters as `<sub>`, since Unicode has no subscript z. Genus names in the same papers can lose a syllable (Pseudococypris read as Pseudocypris).

### Model choice: Sonnet for OCR and all translation; Haiku is not used
Every vision and translation script defaults to Sonnet via `corpus.models`. Haiku fabricates far more in vision OCR (Liassico → "Giassico", which the translator then turned into "Upper Jurassic"; one binomial spelled eight ways in one paper). Haiku 5.5 misreads less but still misreads genus names and collection prefixes (*Beishanlong* as "Beishanglong", JLUM as "ILUM") and "corrects" printed spellings (*Brachyosaurus* → *Brachiosaurus*, "correllation" → "correlation"). In European translation Haiku 5.5 can return a chunk mostly untranslated with `end_turn` and a length ratio near 1, so no guard fires; detect that with a function-word count per paragraph (`und|der|die|das|wurde|von|nicht|mit|ein`, five or more), not the length ratio. In CJK translation it renders Chinese genus names wrongly (大地龙 as "*Dilong* (?)" where Sonnet gives *Tatisaurus*), even with `CJK_TAXON_RULE`.
**Both models substitute well-known taxa for less familiar printed ones** ("(?*Abrictosaurus* sp.)" translated as *Lycorhinus*). After any translation, list the italicized names in the output that don't occur in `.original.md` and check each against the rendered page. Text-layer misreads ("Gaumia lincisa", "Termatosaurus albertif") show up in the same list and are legitimately corrected.
Haiku 5.5 thinks by default, and the thinking counts toward `max_tokens`; `models.request_extras()` turns it off. Sonnet 5.5 rejects `{"type": "disabled"}` with a 400, so the helper sends it only to Haiku. The SDK is pinned at `anthropic==0.46.0`, which predates the `thinking` parameter, so it goes through `extra_body`. Both models can stop with `stop_reason: "refusal"`; `convert_translate.py` treats that as a failed chunk and doesn't cache it.

### Changing the pipeline's models
`corpus.models` (`src/corpus/models.py`) holds `SONNET`, `HAIKU`, `CACHE_COMPATIBLE`, `PRICES` and `request_extras()`. Every cache (vision, translation, tile, specimen) reuses an entry only if its model is in the same `CACHE_COMPATIBLE` group, so a bare constant swap makes any rebuild re-OCR every page. Haiku translation caches are not compatible with Sonnet, so re-running a key first translated on Haiku re-translates every chunk on Sonnet; to keep the old chunks, pass `--model claude-haiku-5-5`. For a model change: confirm the ID on GET /v1/models, change `SONNET`, add the new ID to the same `CACHE_COMPATIBLE` group and to `PRICES`, then test that `cached_page_response` hits on an existing key's page. Check `PRICES` against the pricing page whenever a model changes; Sonnet 5 and 5.5 cost $2/$10 per MTok, and older cost logs at $3/$15 overstate spend by about 1.5×.

## Translation

### The language audit over-reports foreign content; re-measure per paragraph
`scripts/qc_languages.py` runs langdetect over the whole document and flags at ≥25% non-English, which is unreliable on mixed-language papers: English papers with a French *Version abrégée*, Spanish affiliations or long foreign abstracts can score 35-50% foreign. Re-measure by splitting on blank lines, detecting each paragraph over 120 characters, and summing characters per language. Translate only when the foreign language is the majority of body paragraphs; otherwise confirm the English text carries the type specimen, locality and diagnosis and leave it.
Expect this from Comptes Rendus (English + *Version abrégée*), Geobios, Ameghiniana, Revista Brasileira, Cretaceous Research with Iberian authors, and the ICZN Bulletin.
Order of checks: CID garbage → OCR fix → language verdict. A body font that shifts every character by a constant and drops spaces (`7KHPDWHULDOV...` = "The materials..."; leading digits stand in for capitals: `7KH` = The, `03&` = MPC) gives random language verdicts and passes `intake_qc.py` and `qc_scan.py`, because the garbage is plain ASCII. Do not try to decode the shift: italic and bold runs come from a working font, so a blanket shift corrupts them. Vision re-OCR fixes it.

### `qc_languages.py --key` rewrites the whole TRANSLATION_AUDIT.md
`--key` narrows the scan, not the report write: the report comes out containing only that key, deleting every other entry. Run it without `--key`, or run it with `--key` and then `git checkout -- TRANSLATION_AUDIT.md` before staging. Always `git status` after the QC block.

### Bilingual papers: force the source language, then count what is left
Papers with a CJK/Russian/French body and English title, abstract, captions and references defeat the 15% language gate in `convert_translate.py` (a paper 31% CJK can detect as `en`), and a book printed in Chinese and English is skipped with "no non-English language detected". After eyeballing the body, run `--key K --src-lang zh-cn`, one key per run (the flag applies to every key). `scripts/qc_scan.py` counts CJK characters and is the more reliable detector for these.
Even with `--src-lang`, paragraphs in chunks dominated by the English half or by tables can come back still in the source language, with `partial=0` and no warning. Afterwards, count the CJK characters per line outside the reference list and the bilingual figure captions, and translate leftover lines one by one with `convert_translate._translate_once` (same model and prompt). Bilingual captions (`图1 …` + `Fig. 1 …`) and reference entries legitimately survive translation; leave them.

### Translation can leave one chunk untranslated while reporting ok
`scripts/convert_translate.py` can return one chunk that echoes the source while reporting `ok=1, partial=0`. Count residual source-script characters (Russian: `'а'<=c.lower()<='я'`); a few is normal (figure letters, references), thousands clustered mid-document is a missed chunk. Re-translate only that block and splice it into `{key}.md`; leave `.original.md` untouched.

### Translations leave the reference list untranslated by design
`convert_translate.py` keeps cited titles in the source language so they stay findable; a translated Chinese paper can have hundreds of CJK characters, all in the references. When judging a translation by residual source-script characters, split body from references first.

### Verify translations by per-section ratio and invariant counts
The 50% whole-file length gate misses mid-document loss. Compare sections matched by heading text (not by position; the translator changes heading counts): ko/zh→en runs ~1.7-2.1×, and a section at 0.5-0.6 lost content even when the whole file looks fine. Also compare `[FIGURE:` counts and `^|` table-row counts between `.original.md` and `.md`, and the catalogue-number multiset: a translation at an overall 0.93 ratio can still have dropped two figures with their specimen numbers. Grep for model false starts ("Wait, I need to", "Let me redo"). `corpus qc translations` (`--verbose` for a per-chunk table) measures each cached chunk against its source with a CJK expansion fitted per file, and flags cut-off chunks, model false starts and untranslated lines. To redo one bad chunk: re-chunk `.original.md` with `corpus.translate.chunk_plan`, compare to `.runtime/cache/translation/{key}/chunk-NNNN.json`, delete only that chunk's JSON, copy `.original.md` over `{key}.md`, re-run. `MIN_CHUNK_RATIO = 0.8` retries/fails short non-CJK chunks, and `clean_chunk_opening()` strips chunk-opening artefacts. Check formal unit names afterwards ("Poudingue fleuri" became "Flowering Pudding"); restore the original forms.

### Bilingual figure captions: the translator drops them, and the chunk fails as short
Brazilian journals (Derbyana, Geociências, RBP) print every caption twice, in Portuguese then English. The translator can keep one copy on one run and drop every caption on the next. The `MIN_CHUNK_RATIO` retry then rejects the chunk, and every re-run re-translates it and overwrites the cache, so a version you checked can be gone on the next run. Lowering the threshold won't help, because the short version really did lose content. Fix: translate the failing chunk in about three paragraph-boundary pieces with `convert_translate.translate_chunk` (each piece keeps its captions), join them, write the result as `chunk-NNNN.json` with `hash=chunk_cache_key(src)`, delete `chunk-NNNN.short.json`, and re-run the script so it assembles the paper and updates the manifest. Check by caption numbers (`FIGURE n` present once each), not by length. Residual-Portuguese counts will flag "São" in place names; that is a false positive.

### The translator can skip the opening of a chunk, and a cache rebuild loses hand repairs
A translated chunk can begin at the chunk's first `#` heading, dropping the prose before it (in one case ~10,000 characters including a whole bibliography, at a 0.37 ratio). A chunk that opens with a table (a contents page) often comes back without the table, which is harmless in itself. To see what is missing, print the translated chunk's first paragraphs next to the source's; matching paragraphs by capitalised tokens fails on German. Fix by translating only the missing slice and splicing it into `{key}.md`. Do not rebuild `{key}.md` from the chunk cache: hand repairs live only in the markdown, and a rebuild silently reverts them. Find a chunk's span in the markdown by the tail of the previous chunk and the head of the next. `clean_chunk_opening()` drops invented opening headings ("# Translation", "# [BEGINS TRANSLATION]"); remove any that slip through.

### Chinese translations drop 上/下 from formation names
上沙溪庙组 / 下沙溪庙组 are the Upper and Lower Shaximiao Formations, separate units; the translator can render them as bare "Shaximiao Formation", turn 底部 ("base") into "lower part", or invent forms ("Shangxiamiao", "Xiasha Stream Formation"). The same papers show transliteration slips in place names (七克台 as "Qike" for Qiketai, 七里峡 as "Qilixi" for Qilixia), wrong ages and a paper's own genus mistranslated. Before citing a horizon from a translated Chinese paper, check the unit name against the text layer (`pypdfium2`, grep the Chinese), and grep translations for bare "Shaximiao Formation" next to a place name. A corpus check can count 上/下沙溪庙组 and 上/下禄丰组 in every Chinese text layer against the English; other 上/下 pairs need the same check.
Spanish *miembro* is both "limb" and "member": grep Spanish translations for limb/leg next to a formation name ("the hind limb of the Bajo Barreal Formation" for *miembro inferior*, the lower member).

### Translation on top of garbled OCR: re-OCR, don't patch numbers
When marker's OCR shattered digits and the text was then translated, the translator reconstructs every number and sometimes guesses (metatarsal II 57→87, coracoid 60→600, a column header 高 "height" given as "width"). Checking against the source text layer finds only some of these; re-OCR finds all. Re-OCR, then re-translate, and verify each changed value against a rendered crop. Delete the stale `.original.md` and translation cache first. Signature: `conversion.notes` mentions translation on a `tool: marker` entry whose PDF is a pre-2000 scan.

### Re-converting a translated key: delete both .original.md copies first
`convert_translate.py` writes `markdown/{key}.original.md` and `.runtime/cache/translation/{key}/original.md` only if they do not exist yet. After a replacement re-OCR or re-conversion, both still hold the previous version's source text while `{key}.md` becomes the new translation. Before re-translating: `rm -f markdown/{key}.original.md` and clear `.runtime/cache/translation/{key}/` (hash-keyed chunks are checked per chunk, but the cached `original.md` is not). Detector: after translating, `git status markdown/{key}.original.md` must show modified. If forgotten, rebuild it from the new source (for vision keys, the `markdown` field of each `.runtime/cache/vision/{key}/page-*.json` joined with `\n\n---\n\n`). This is easy to miss and easy to report as fixed when it is not.

### After any bulk re-OCR, audit stale translation backups, but read before deleting
If `convert_translate.py` ran on a broken marker conversion, it backed that up as `.original.md`; when vision OCR later replaces `markdown/{key}.md`, the stale backup and `translated_*` fields survive, and `translated_from` is langdetect noise on garbage ("fr" on an English Nature paper). Sweep for keys with `conversion.translated_at` whose `.original.md` is absent or tiny, then read each backup: a backup under 2 KB can be a legitimate one-page note. `haiku` strings in manifest notes refer to the translation model, not OCR.

### Translation cache directories may sit under pre-rename keys
`.runtime/cache/translation/*/` directories can carry old key names while the live keys have an a/b/c suffix. Resolve a cache dir to its live key by hashing its `original.md` against `markdown/*.original.md`, not by directory name.

### Some markdown files are human translations; re-converting destroys them
Some markdown files are published human English translations, originally `.doc` files. `/intake` on a replacement PDF overwrites `markdown/{key}.md` unconditionally.
Before re-converting a key whose `conversion.tool` is `textutil-markdownify`, read the first 500 bytes for a "translated by" line. Preserve both: convert, move the result to `{key}.original.md`, restore the translation to `{key}.md`, set `conversion.original_markdown_path`, `conversion.translation = "human (<translator>)"` and `conversion.notes`.

### Large foreign monographs: present cost and quality, let the user decide
Do not bulk-translate a ~100+ page foreign monograph by default. Cost is the weak argument (about $1-2 for 190 pages); the durable concern is that nobody proofreads that much machine-translated anatomy. Completeness is verifiable (source function-word counts before/after, failed-chunk markers, size ratio, survival of taxa, specimen prefixes and formations); correctness of technical terms is not. Offer the middle path: translate only the systematics, diagnosis and description sections. Always confirm `markdown/{key}.original.md` exists and commit both files. Check pricing via the claude-api skill, not memory.

## Cleanup scripts

### Rotated "Journal Pre-proof" watermark lands one letter per prose line
On Elsevier pre-proof pages without a table, marker glues one watermark letter to the front of each prose line (`f o lambeosaurines…`, `r p Our osteohistological…`); read downward the letters spell "Journal Pre-proof" backwards with gaps. Appearance cannot gate this: affiliation superscripts (`a Institut Català…`), sentences starting with "A", and `A B S T R A C T` look the same. `strip_preproof_rotated()` in `scripts/clean_frontmatter.py` chains candidate lines (gap ≤ 4, chain ≥ 5) and cuts only when the letters are a *subsequence* of `JOURNALPREPROOF` in either direction (marker drops letters). Trailing-edge letters are deliberately left alone (a trailing "a" is indistinguishable from prose).

### Shredded "ACCEPTED MANUSCRIPT" watermark vs shredded rotated table headers
On Elsevier accepted manuscripts with a table, marker can read the watermark one letter per row (`| T<br>Zhu et al., 2007 |`). Rotated column headers shred identically ("Characters in Xunmenglong", `R<br>A<br>D<br>I<br>U<br>S`). `scripts/clean_frontmatter.py` gates on two things: the rest of the cell has no further `<br>`, and `_is_watermark_run()` requires a contiguous slice of "ACCEPTEDMANUSCRIPT" forward or reversed. Never strip a lone capital (character tables use one-letter presence codes). Verify a sweep by character multiset: diff against `git show HEAD:file`, assert nothing added and every removed character is in the watermark alphabet plus `<br>|` whitespace.

### Extending clean_frontmatter.py: anchor rules learned per publisher
- Anchor on the first cover match and extend over the contiguous short run; a "last match in HEAD_LIMIT" rule cuts the title and author from facsimiles that reprint an original colophon. Print the resulting head of every affected file, not just the removed blocks.
- Some covers are not head prefixes: Palaeontologia Electronica and PeerJ put licence/sidebar text after the abstract, handled by a paragraph denylist (`PHRASE_JUNK`) anchored `^…$`. The PeerJ DOI pattern is pinned to `10.7717`; many files cite a PeerJ DOI without carrying the sidebar. Do not strip "Corresponding author <name> <email>" (it is real metadata). Keep ZooBank LSID headings.
- The Elsevier/ScienceDirect masthead has a headless variant (marker drops the "Contents lists available at ScienceDirect" anchor): the fallback requires the run to start at block 0 and the homepage line to name an Elsevier domain (bare "journal homepage:" is also T&F).
- Iterate `--apply` to a fixed point (it can take four passes), and audit diffs by net-removed lines: the stripper normalizes a missing trailing newline, so raw `-` lines overstate deletions.
- Left uncovered on purpose: Science Advances' end-of-paper dates (past HEAD_LIMIT) and sidebars just past the limit. Do not raise HEAD_LIMIT globally.
- Covers handled: T&F ×3, BioOne, JSTOR, Elsevier AM, Elsevier published + headless masthead, BHL, Royal Society, UMI/ProQuest, ZORA, UAB DDD, EBSCO, eScholarship, Yale Peabody/EliScholar, Palaeontologia Electronica, PeerJ.

### Word files: textutil drops automatic list numbering
textutil (-> HTML -> markdownify) loses Word's automatic numbering, in both HTML and plain-text output. In a character list that is a real loss, because the matrix columns map to the numbers. After converting any .doc/.docx with a numbered list, count the items against what they index (matrix columns, figure references) before restoring numbers; if the counts disagree, do not guess. For .docx, the numbers can be rebuilt from `word/document.xml`: keep a counter per `numId`, starting at the level's `w:start`. A level with no `w:start` counts from 0 per the OOXML spec, which is how character-state lists match 0-based matrix codes. Check afterwards: characters complete, each state list 0..k, matrix width = character count.

## Extracting a figure image from a PDF: four traps

- **Caption page is not always the figure page.** PLOS papers can put a caption on one page and its image on the page before, sharing a page with the next figure's image. Taking "the image on the caption's page" silently gives the wrong figure. Look at what you extracted.
- **White-on-black extractions.** 1-bit image masks (no colour space) and 8-bit Separation (spot-ink) images can come out inverted when the raw image is converted to RGB (about 8% of tree figures). Render the image's page rectangle instead.
- **Flipped or rotated placement.** About 3% of embedded figures are drawn with a flip or 90° matrix, so the raw pixels are upside down or mirrored. Check the image's placement matrix on the page.
- **Labels outside the raster.** About 5% of figures are a label-free raster with the text set as PDF text on top; only a page render (or the text layer) has the names.
