# Working on the code

### Shared code lives in the corpus package; scripts are entry points
The helpers scripts share live in `src/corpus/`, installed editable into `.runtime/venv` (`pip install -e . --no-deps`; `scripts/bootstrap.sh` does it): `config` (ROOT and every path, `data_repo()`, `require_env()`, `user_agent()`), `io` (atomic writes in the manifest's exact JSON format, tolerant `read_json`), `keys` (NFC, validation, `key_arg` for argparse, `read_keys_file`), `manifest` (`load`/`commit`/`update`/`save`, `entry_skeleton`), `bib` (`bib_path()`, `citation_venue()`, `is_thesis()`, and `page_range()`, a citation's printed page range; a book's "250 pp." is not one), `supplementary`, `models` (model IDs, `cache_model_ok()`, `cost()`), `progress`, `pdf.text`/`pdf.build`/`pdf.render`/`pdf.pages`/`pdf.layout`, `vision.cache`/`vision.client`/`vision.ocr`, `fetch.http`/`fetch.doi_list`, `fetch.tier` (which keys an acquisition tier tries; `record_pdf`/`record_failure`, which never write a failure over a real source), `fetch.unpaywall`, `bhl` (index connection, the volume matcher, the JP2 stitch), `status`, `md`, `words`, `repair`, `cli`. Writes: `io.atomic_write_text/bytes/json`, and `io.atomic_path()` for a library that saves to a path (pikepdf). Logs: `io.jsonl_append`. Downloads too large for memory: `fetch.http.download()` (streams to a .part file); `fetch.http.head()`. Before writing a helper in a script, look there; never import one script from another.

### Test a script that writes in a throwaway CORPUS_ROOT, never on the archive
`corpus.config.ROOT` honours `CORPUS_ROOT`. Build a folder in the scratchpad with a `manifest.json` holding only the entries needed, copy in the PDF (and `.runtime/cache/vision/{key}/` for a vision key, so every page cache-hits and no API call is made), and run the script with `CORPUS_ROOT=that/folder`. For `convert_vision.py` pick a key whose `.runtime/cache/vision/{key}/page-*.json` name a model `cache_model_ok` accepts for the current one (`corpus.models`), or every page is a paid API call. The same approach works for `convert_marker.py` (compare the output with the committed markdown) and `pdf_extract_pages.py`/`pdf_append_pages.py`. Copy `.env` in only when a script checks for the key, and delete it after.
The test suite does the same for every test: `tests/conftest.py` sets `CORPUS_ROOT` to an empty temporary folder before anything imports `corpus.config`, so a test that calls a script's `main()` in-process cannot reach the real corpus even if it forgets to stub a write (one once replaced `manifest.json` with its fixture). Give a test that needs data its own `tmp_path` corpus, passed as `CORPUS_ROOT` to a subprocess or monkeypatched onto `corpus.config`; stub `manifest_commit` when calling a `main()` that commits.

### Before committing code: lint, tests, and a before/after dry-run diff
`./.runtime/venv/bin/ruff check scripts src tests` (pyflakes + syntax; clean) and `./.runtime/venv/bin/python -m pytest -q` (82 tests, ~2.5 s, temporary directories only). For a refactor that should not change behaviour, capture the dry-run output of the affected scripts before and after (the repair scripts are dry-run unless `--apply`) and diff; importing every script and running `--help` catches broken imports but not undefined names inside functions, which ruff does. Some scripts have no dry-run at all (`convert_vision.py`, which calls the API): don't run those to "check" them.

### The pre-commit hook flags test data that looks like a secret
A test (or a note) that spells out a key variable name followed by "=" and a value is refused by `.githooks/pre-commit`, even with a fake value. Assemble such strings at runtime (`"ANTHROPIC_" + "API_KEY=" + ...`) and describe the pattern in words in prose.

### Text-layer repairs are package modules; `corpus repair all` runs them in one pass
`src/corpus/repair/{dash,symbols,accents,diaeresis,ref_links,fused_calls,control_glyphs}.py` each expose `repair(doc, md, key, quiet=...) -> (new_md, stats)` with no file I/O; their `main()` is the per-repair command, and the matching scripts (`corpus repair dash`, `corpus repair symbols` and the rest) are two-line wrappers. `corpus repair all` (`corpus/repair/__init__.py`) checks each repair's eligibility, opens the PDF once only if one applies, runs them in `REPAIRS` order and writes once. A new repair goes in as a module with `repair()` and `main()` plus a `REPAIRS` entry; `control_glyphs` stays out of the pass because it needs a hand-made map per paper.

### Converted markdown is written through `corpus.pages`
Markdown keeps a `<!-- page N -->` marker at the start of each PDF page, which the web reader uses to show the text beside the same PDF page. A converter writes them (`corpus.pages.join`, or `from_marker_output` for marker's `--paginate_output`). Anything that rewrites a converted file saves it with `corpus.pages.write_markdown(path, new)`, which refuses a result whose markers changed; one that removes whole pages of junk calls `restore_dropped(old, new)` first so the emptied page keeps its marker. A script that searches the text for numbers (line numbers, footnote calls) skips marker lines with `pages.in_marker(text)`. Test whether a file has text with `pages.is_empty(path)`, not its size: a scan with no text layer comes out of marker as markers alone.

### The web app's browser code follows the open-paleo JavaScript style
`src/corpus/web/static/*.js` is plain JavaScript served as written: no build step, so running `corpus web` needs only Python. It follows the rules of the data repository (`scripts/CONTRIBUTING.md` there) and the tree extractor, enforced by `eslint.config.js` (the same `@stylistic` rules): 4-space indentation, Allman braces, double quotes, semicolons, trailing commas, braces on every `if`/`for` body and a blank line after each, arrow functions for callbacks, `??` for fallbacks, camelCase names written out in full (`element`, not `el`), PascalCase only for classes, no `// ----` dividers. Types are JSDoc (`@param {string}`, `@typedef`, `Array<T>`), checked by `tsc --checkJs`; PDF.js's types come from the `pdfjs-dist` development package of the vendored version, through `static/pdfjs/pdf.min.d.mts`. CSS has 4-space indentation and one declaration per line except in one-declaration rules. Before committing a change there: `npm ci` once, then `npm run lint` and `npm run typecheck` (CI runs both). Dependencies are pinned to exact versions (`.npmrc` sets `save-exact`).

### Every script parses its arguments, even with no options
A script without argparse treats `--help` as a run, so a `--help` probe can rebuild an index or overwrite `manifest.json`. Every entry point builds an `ArgumentParser` (an empty one is enough), and `test_every_script_parses_its_arguments` fails on a script without one. `bootstrap.py` also refuses a manifest that has entries unless `--force`.

### Sort with a full key when the result is cut
Python randomises set order per run (PYTHONHASHSEED), so sorting a set by a partial key (word length alone) and keeping the first n gives different results on different runs; `bhl_match.fts_query` matched the same paper differently from run to run this way. Any sort feeding a `[:n]` cut or a "first wins" choice needs a key that orders every item (`(-len(w), w)`).

### A script is named after its command
`corpus clean frontmatter` is `scripts/clean_frontmatter.py`: `{group}_{name}.py`, with hyphens as underscores, and a test enforces it. The groups say what kind of step a script is: `fetch` and `bhl` acquire, `intake` registers, `pdf` prepares PDFs, `convert` makes markdown, `repair` restores text from the PDF's own text layer, `clean` fixes the markdown by itself, `qc` reports, `manifest` refreshes from the bib, and `index`, `search` and `web` read the result. Pick the group by that rule, then the name. `repair` takes script commands beside the `corpus.repair` modules, as long as the name is not one of the modules or `all`.

### A script becomes a `corpus` command by declaring it; private repositories extend the command the same way
There is no command table. Each script that should be a command says so in a comment near its top, `# corpus-command: convert marker | PDF -> markdown via marker (text layer)` (one or two words, `|`, a one-line summary), and `corpus` reads those lines from the scripts present in `scripts/` without importing them (`corpus.cli.commands()`). So a checkout lists exactly the commands it can run, and the public repository cannot advertise a script it doesn't ship. A private repository built on the public one adds commands by adding scripts with a declaration and never edits `cli.py`, so merging public changes cannot conflict over the command list. Two scripts declaring the same command, or a script declaring a built-in (`status`, `repair`, `run`, `help`, `list`), is an error, and `test_every_declared_command_is_unique_and_its_script_exists` checks the repository's own scripts. Keep the summary current when a script's behaviour changes.
