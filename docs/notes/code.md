# Working on the code

### Shared code lives in the corpus package; scripts are entry points
Since 2026-10-31 (code review, commits 39530c52..2c115029) the helpers every script used to copy live in `src/corpus/`, installed editable into `.runtime/venv` (`pip install -e . --no-deps`; `scripts/bootstrap.sh` does it): `config` (ROOT and every path, `data_repo()`, `require_env()`, `user_agent()`), `io` (atomic writes in the manifest's exact JSON format, tolerant `read_json`), `keys` (NFC, validation, `key_arg` for argparse, `read_keys_file`), `manifest` (`load`/`commit`/`update`/`save`, `entry_skeleton`), `bib`, `supplementary`, `models` (`cost()`), `progress`, `pdf.text`/`pdf.build`/`pdf.render`/`pdf.pages`, `vision.cache`/`vision.client`/`vision.ocr`, `fetch.http`/`fetch.doi_list`, `fetch.tier` (which keys an acquisition tier tries; `record_pdf`/`record_failure`, which never write a failure over a real source), `fetch.unpaywall`, `bhl` (index paths, the volume matcher, the JP2 stitch), `bib.page_range` (a citation's printed page range; a book's "250 pp." is not one), `status`, `md`, `words`. Writes: `io.atomic_write_text/bytes/json`, and `io.atomic_path()` for a library that saves to a path (pikepdf). Logs: `io.jsonl_append`. Downloads too large for memory: `fetch.http.download()` (streams to a .part file); `fetch.http.head()`. Before writing a helper in a script, look there; never import one script from another (`ocr_spread_pdf.py` used to import 15 names from `convert_with_vision.py`).

### Test a script that writes in a throwaway CORPUS_ROOT, never on the archive
`corpus.config.ROOT` honours `CORPUS_ROOT`. Build a folder in the scratchpad with a `manifest.json` holding only the entries needed, copy in the PDF (and `.runtime/cache/vision/{key}/` for a vision key, so every page cache-hits and no API call is made), and run the script with `CORPUS_ROOT=that/folder`. For convert_with_vision pick a key whose `.runtime/cache/vision/{key}/page-*.json` name a model `cache_model_ok` accepts for the current one (`corpus.models`), or every page is a paid API call; also used for convert_with_marker (furin2006a: byte-identical to the committed markdown), extract/append_pdf_pages. Copy `.env` in only when a script checks for the key, and delete it after.

### Before committing code: lint, tests, and a before/after dry-run diff
`./.runtime/venv/bin/ruff check scripts src tests` (pyflakes + syntax; clean) and `./.runtime/venv/bin/python -m pytest -q` (79 tests, ~2.5 s, temporary directories only). For a refactor that should not change behaviour, capture the dry-run output of the affected scripts before and after (the repair scripts are dry-run unless `--apply`) and diff; importing every script and running `--help` catches broken imports but not undefined names inside functions, which ruff does. Some scripts have no dry-run at all (`convert_with_vision.py`, which calls the API): don't run those to "check" them.

### The pre-commit hook flags secret-shaped test data
A test (or a note) that spells out a key variable name followed by "=" and a value is refused by `.githooks/pre-commit`, even with a fake value. Assemble such strings at runtime (`"ANTHROPIC_" + "API_KEY=" + ...`) and describe the pattern in words in prose.

### Text-layer repairs are package modules; `corpus repair all` runs them in one pass
`src/corpus/repair/{dash,symbols,accents,diaeresis,ref_links,fused_calls,control_glyphs}.py` each expose `repair(doc, md, key, quiet=...) -> (new_md, stats)` with no file I/O; their `main()` is the per-repair command, and the old `scripts/repair_*.py` / `restore_symbol_glyphs.py` are two-line wrappers. `corpus repair all` (`corpus/repair/__init__.py`) checks each repair's eligibility (the same scope as its old `--all`), opens the PDF once only if one applies, runs them in REPAIRS order and writes once. On 731 papers rebuilt from git as they were before the corpus-wide repairs (parent of 03d057a), the single pass and the six old scripts run in sequence with `--apply` gave byte-identical markdown for all 725 changed files. A new repair goes in as a module with `repair()` and `main()` plus a REPAIRS entry; `control_glyphs` stays out of the pass because it needs a hand-made map per paper.

### Every script parses its arguments, even with no options
A script without argparse treats `--help` as a run: on 2026-11-02 `bhl_index.py --help` rebuilt the BHL index, and `bootstrap.py --help` would have overwritten manifest.json. Every entry point now builds an `ArgumentParser` (an empty one is enough), and `test_every_script_parses_its_arguments` fails on a script without one. `bootstrap.py` also refuses a manifest that has entries unless `--force`.

### Sort with a full key when the result is cut
`bhl_match.fts_query` sorted title words by length alone and kept the first six; equal-length words stayed in set order, which Python randomises per run (PYTHONHASHSEED), so the same paper could be queried with different words and matched differently on each run (found 2026-11-02 comparing two runs). Any sort feeding a `[:n]` cut or a "first wins" choice needs a key that orders every item (`(-len(w), w)`).

### A script becomes a `corpus` command by declaring it; private repositories extend the command the same way
There is no command table. Each script that should be a command says so in a comment near its top, `# corpus-command: convert marker | PDF -> markdown via marker (text layer)` (one or two words, `|`, a one-line summary), and `corpus` reads those lines from the scripts present in `scripts/` without importing them (`corpus.cli.commands()`). So a checkout lists exactly the commands it can run: the public repository cannot advertise a private or not-yet-published script, which the old shared table did (11 of 45 entries had no script there, 2026-11-02). A private repository built on the public one adds commands by adding scripts with a declaration and never edits `cli.py`, so merging public changes cannot conflict over the command list. Two scripts declaring the same command, or a script declaring a built-in (`status`, `repair`, `run`), is an error, and `test_every_declared_command_is_unique_and_its_script_exists` checks the repository's own scripts. Keep the summary current when a script's behaviour changes.
